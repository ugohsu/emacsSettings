# レッスン 3: 変更を捨てる・コミットをやり直す (`03-fix`)

| キー | 動作 | git コマンド |
|---|---|---|
| `x` (変更の上で) | 変更を捨てて、最後のコミットの状態に戻す (元に戻せない) | `git restore ファイル` |
| `x` (`Untracked files` のファイルで) | ファイルを消す (ゴミ箱に移す) | `rm ファイル` (`git clean`) |
| `c e` | stage した変更を、直前のコミットに足す (メッセージはそのまま) | `git commit --amend --no-edit` |
| `c w` | 直前のコミットのメッセージだけを直す | `git commit --amend --only` |
| `c a` | 直前のコミットを作り直す (stage した変更を足し、メッセージも直す) | `git commit --amend` |
| `o` | ブランチを、指定したコミットまで戻す (取り消したコミットの変更はファイルに残る) | `git reset コミット` |
| `O s` / `O m` / `O h` | 戻し方を選んで戻す (soft / mixed / hard。下の表) | `git reset --soft` / `--mixed` / `--hard` |
| `_ _` (コミットの上で) | そのコミットを打ち消す、新しいコミットを作る | `git revert コミット` |
| `-` (コミットの上で) | そのコミットを打ち消す変更を作るだけ (コミットはしない) | `git revert --no-commit コミット` |

reset の 3 つの種類 (どれもブランチの先頭を、指定したコミットに動かす。違うのは、取り消したコミットの変更をどこに残すか)。

| 種類 | ステージ | 作業ツリー (ファイル) | 使いどころ |
|---|---|---|---|
| soft (`O s`) | 残す | 残す | コミットだけを取り消す。変更は stage されたまま残るので、すぐにコミットし直せる |
| mixed (`o`、`O m`) | 戻す | 残す | コミットと stage を取り消す。変更はファイルに残る |
| hard (`O h`) | 戻す | 戻す | 変更ごと捨てる。ファイルも書き換わる (戻すにはレッスン 10 の reflog を使う) |

**push する前と後で、やり方を変える**: まだ push していないコミット (自分の手元にしかないコミット) は、
amend や reset で作り直してよい。push したコミットを作り直すと、ほかの人の手元の履歴と食い違うので、
revert で「打ち消すコミット」を足す。

## 変更を捨てる

- [ ] 右の dired で `03-fix` に入り、`SPC g`。`Unstaged changes` の `draft.md` で `TAB` を押す。
      目的の行に `(ためし書き。あとで消す)` を書き足した変更がある。
- [ ] hunk の上で `x` を押し、確認に `y` で答える。変更が消え、ファイルが最後のコミットの状態に戻る。
      **捨てた変更は git にも残っていないので、元に戻せない** (`x` は確認が出たら必ず読む)。
- [ ] `Untracked files` を `TAB` で開き、`scratch.tmp` で `x` → `y`。ファイルがゴミ箱に移る。
      ステータス画面から変更の見出し (`Unstaged changes` など) がなくなる (作業ツリーが最後のコミットと同じ状態)。

## 直前のコミットを直す

- [ ] `C-x C-f` で `draft.md` を開き、最後に `回答は 100 件。` の行を書き足して `:w`。`SPC g` で戻る。
- [ ] `draft.md` を `s` で stage し、`c e` を押す。メッセージのバッファは開かず、直前のコミット `第 3 節をついか` に今の変更が足される。
- [ ] `Recent commits` を `TAB` で開き、一番上のコミットで `SPC` を押す。そのコミットの差分に `回答は 100 件。` も入っている。
      (amend したコミットは、中身が変わったので ID も変わる。前の ID のコミットは、作り直されて別のものになった)
- [ ] `c w` を押す。直前のコミットのメッセージが入ったバッファが開くので、`ついか` を `追加` に直して `ZZ`。
      `Recent commits` の一番上が `第 3 節を追加` になる。

`c a` は `c e` と `c w` を一度にするもの (stage した変更を足し、メッセージのバッファも開く)。

## reset でコミットを取り消す

- [ ] `Recent commits` の `方法に人数を書く` の行で `o` を押す。`Reset main to` と聞かれ、既定 (`default`) がその行のコミットになっているので `RET`。
      `第 3 節を追加` のコミットが履歴から消え、その変更が `Unstaged changes` に残る (mixed)。
- [ ] `S` → `c c` で、`第 3 節を追加` とコミットし直す (これで元どおり。ID は前と違う)。
- [ ] もう一度 `方法に人数を書く` の行で、今度は `O s` → `RET` を押す (soft)。変更は `Staged changes` に残る。
      `c c` → `第 3 節を追加` でコミットし直す。
- [ ] hard を試すために、いらないコミットを作る。`C-x C-f` で `draft.md` を開き、`いらない行` と書き足して `:w`。
      `SPC g` で戻り、`s` → `c c` → `いらないコミット` → `ZZ`。
- [ ] `Recent commits` の `第 3 節を追加` の行で `O h` → `RET`。`いらないコミット` が履歴から消え、`draft.md` からも `いらない行` が消える。

## revert でコミットを打ち消す

- [ ] `Recent commits` の `方法に人数を書く` の行で `_` を押す。revert のメニューが出るので、もう一度 `_` (Revert commit(s)) を押す。
      `Revert commit` と聞かれ、既定がその行のコミットになっているので `RET`。
- [ ] メッセージのバッファに `Revert "方法に人数を書く"` と入っているので、そのまま `ZZ`。
      `draft.md` の `100 人に質問した。` が `質問した。` に戻る。元のコミットは履歴に残ったまま、打ち消すコミットが 1 つ増える。
- [ ] `Recent commits` を見ると、`方法に人数を書く` と、それを打ち消す `Revert "方法に人数を書く"` の両方が並んでいる。
      push したあとで取り消したいときは、このやり方を使う。
