# レッスン 6: マージと衝突の解決 (`06-merge`)

**マージ**は、ほかのブランチの変更を今のブランチに取り込むこと。取り込み方は 2 通りある。

- **早送り (fast-forward)**: 今のブランチが、取り込むブランチの途中のコミットにある (自分の側に新しいコミットがない) ときは、
  名札を先に進めるだけで済む。新しいコミットはできない。
- **マージコミット**: 両方のブランチに新しいコミットがある (分かれている) ときは、2 つをまとめた「マージコミット」を新しく作る。

両方のブランチが同じ行を別々に書き換えていると、git はどちらにするか決められず、**衝突 (conflict)** として止まる。
そのときは、ファイルに書かれた衝突の印を見て、人が内容を決める。

```
<<<<<<< HEAD
(今のブランチ (main) の内容)
=======
(取り込むブランチの内容)
>>>>>>> conflict
```

| キー | 動作 | git コマンド |
|---|---|---|
| `m m` | 指定したブランチを、今のブランチに取り込む | `git merge --no-edit ブランチ` |
| `m` の画面で `-n` を付けて `m` | 早送りできるときも、マージコミットを作る | `git merge --no-ff ブランチ` |
| (衝突したファイルで) `gu` / `gl` / `ga` | 衝突した箇所を、上 (今のブランチ) / 下 (取り込むブランチ) / 両方 の内容にする (`C-c ^ u` / `C-c ^ l` / `C-c ^ a` でも) | (ファイルを書き換えるのと同じ) |
| (衝突したファイルで) `]]` / `[[` | 次 / 前の衝突した箇所へ (`gj` / `gk` でも) | |
| (マージの途中で) `m m` | 衝突を解決したあと、マージコミットを作る (`c c` でも) | `git commit` |
| (マージの途中で) `m a` | マージをやめて、始める前の状態に戻す | `git merge --abort` |

ここでは、カレーのレシピ (`recipe.md`) に、ほかの人が作った 4 つのブランチを取り込む。

## ブランチを見る

- [ ] 右の dired で `06-merge` に入り、`SPC g`。`l b` で、すべてのブランチをグラフで見る。
      `fast` は `main` の 1 つ先にある。`feature`・`conflict`・`conflict2` は、`main` の 1 つ前のコミットから枝分かれしている。
      各ブランチの先頭で `SPC` を押して、何を変えたのかを見ておく。`q` で閉じる。

## 早送りのマージ

- [ ] `m m` を押し、`Merge` と聞かれたら `fast` を選んで `RET`。
      新しいコミットはできず、`main` の名札が `fast` と同じコミットまで進む (`Head:` が `盛り付けの手順を足す` になる)。
      `` ` `` で見ると、git の出力に `Fast-forward` と出ている。

## マージコミットを作るマージ

- [ ] `m m` → `feature`。`main` と `feature` は分かれているので、マージコミット `Merge branch 'feature'` ができる。
      `recipe.md` に、`feature` で足した `トマト 1 個` と、`main` 側の変更の両方が入っている。
- [ ] `l l` を押すと、グラフで 2 本の線が `Merge branch 'feature'` で 1 つになっている。`q` で閉じる。

## 衝突を解決する

- [ ] `m m` → `conflict`。`main` と `conflict` が同じ行 (`## メモ` の辛さの行) を書き換えているので、衝突して止まる。
      ステータス画面に `Merging conflict (1)` と出て、`recipe.md` が `unmerged` (解決していない) になる。
- [ ] `Unstaged changes` の `unmerged   recipe.md` で `TAB` を押すと、衝突の印が見える。
- [ ] その行で `RET` を押して `recipe.md` を開く。カーソルを衝突の箇所 (`<<<<<<<` の行から `>>>>>>>` の行までの間) に置き
      (なければ `gg` → `]]` で移る)、`gl` を押す。下 (取り込む `conflict` 側) の `- 辛さは甘口` だけが残り、印が消える。
      (`gu` なら上 (`main` 側)、`ga` なら両方が残る。印を手で消して、自分で書き直してもよい)
- [ ] `- 辛さは甘口` の行を `- 辛さは甘口 (子どもも同じものを食べる)` と書き直して `:w` で保存する。
      衝突の印がなくなったファイルを保存すると、Emacs が自動で stage する (`git add recipe.md`)。
- [ ] `SPC g` で戻る。`recipe.md` が `Staged changes` に移っている (移っていなければ `s` で stage する)。
- [ ] `m` を押すと、マージの途中なので、メニューが `Commit merge` (`m`) と `Abort merge` (`a`) だけになっている。`m` を押す。
      メッセージのバッファに `Merge branch 'conflict'` と入っているので、そのまま `ZZ`。マージが終わる。

## マージをやめる

- [ ] `m m` → `conflict2`。これも同じ行を変えているので衝突する。
- [ ] 今回は取り込まないことにして、`m a` を押し、確認に `y` で答える。マージを始める前の状態に戻る (`Merging` の表示も消える)。

衝突は、同じファイルの同じあたりを、別々のブランチで書き換えたときに起きる。
作業を始める前に最新の `main` を取り込んでおく、ブランチを長く分けたままにしない、などで減らせる。
