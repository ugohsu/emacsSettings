# レッスン 9: コミットを整理する (`09-rebase`)

作業中は「WIP (作業中)」「誤字」のような細かいコミットが積み重なりがち。ほかの人に見せる (push する) 前に、
まとめたり、メッセージを直したり、いらないものを消したりして、読みやすい履歴に整える。これに **rebase** を使う。

rebase は、コミットを 1 つずつ「付け直す」操作。付け直したコミットは、中身が同じでも ID が変わる (別のコミットになる)。
そのため、**push してほかの人と共有したコミットは rebase しない** (ほかの人の手元の履歴と食い違う)。
magit は、push 済みのコミットを書き換えようとすると確認を出す。

| キー | 動作 | git コマンド |
|---|---|---|
| `r i` (コミットの上で) | そのコミットから先を、並べ替える・まとめる・消す・メッセージを直す | `git rebase -i コミット^` |
| (rebase の一覧で) `p` / `r` / `e` | pick (そのまま使う) / reword (メッセージを直す) / edit (そこで止めて直す) | |
| (rebase の一覧で) `s` / `f` | squash / fixup (1 つ上のコミットにまとめる。squash はメッセージも合わせて書き直し、fixup は上のメッセージだけを使う) | |
| (rebase の一覧で) `d` | そのコミットを消す (行がコメントになる。もう一度押すと戻る) | |
| (rebase の一覧で) `M-k` / `M-j` | 行を上 / 下に動かす (コミットの順番を変える) | |
| (rebase の一覧で) `ZZ` / `ZQ` | rebase を始める / やめる | |
| `c F` | stage した変更を、選んだコミットにすぐにまとめる | `git commit --fixup=コミット` → `git rebase -i --autosquash` |
| `c f` → (あとで) `r f` | 修正用のコミット (`fixup! …`) を作っておき、あとでまとめる | 同上を 2 回に分けて実行 |
| `r w` / `r k` (コミットの上で) | そのコミットのメッセージだけを直す / そのコミットを消す | |
| `r e` | 今のブランチを、指定したブランチの先に付け直す | `git rebase ブランチ` |
| (rebase の途中で) `r r` / `r s` / `r a` | 続ける / そのコミットを飛ばす / やめて元に戻す | `git rebase --continue` / `--skip` / `--abort` |

## rebase -i でまとめる・直す・消す

- [ ] 右の dired で `09-rebase` に入り、`SPC g`。今いるのはブランチ `feature`。`l l` で履歴を見る。
      `main` から分かれたあと、`グラフを描く関数を追加`・`凡例を追加`・`誤字`・`WIP`・`デバッグ用の print` の 5 つのコミットがある。
      各コミットで `SPC` を押して、何を変えたのかを見ておく (`誤字` は、`グラフを描く関数を追加` で入れた文字の直し)。
- [ ] 履歴の `グラフを描く関数を追加` の行で `r i` を押す。そのコミットから先の 5 つが、古い順に並んだ一覧 (`git-rebase-todo`) が開く。
      各行の先頭の `pick` が、そのコミットをどう扱うかの指示。下の `#` の行に、使えるキーの説明がある。
- [ ] `誤字` の行で `M-k` を押し、`グラフを描く関数を追加` のすぐ下に動かす。続けて `f` を押す (`fixup`)。
      `誤字` が、1 つ上の `グラフを描く関数を追加` にまとめられ、メッセージは上のものだけが残る。
- [ ] `WIP` の行で `r` を押す (`reword`)。あとでメッセージを書き直す。
- [ ] `デバッグ用の print` の行で `d` を押す。行がコメントになり、このコミットは消える。
- [ ] `ZZ` で rebase を始める。`WIP` のところで止まって、メッセージのバッファが開くので、`色の設定を追加` に書き直して `ZZ`。
- [ ] rebase が終わる。`l l` で見ると、`グラフを描く関数を追加`・`凡例を追加`・`色の設定を追加` の 3 つになっている。
      `グラフを描く関数を追加` で `SPC` を押すと、誤字が直った内容になっている。

途中でやめたくなったら、一覧で `ZQ` を押す (何も変わらない)。rebase の途中 (止まっているとき) なら `r a` で始める前に戻せる。

## あとから直したくなった変更を、前のコミットにまとめる

- [ ] `C-x C-f` で `legend.py` を開き、`print("-", name)` の `-` を `・` に直して `:w`。`SPC g` で戻り、`s` で stage する。
      これは `凡例を追加` のコミットに入れておきたい変更とする。
- [ ] `c F` を押すと、どのコミットにまとめるかを選ぶ履歴のバッファが開く。`凡例を追加` の行で `C-c C-c` を押す (`.` でもよい)。
      修正用のコミットを作って、すぐに `凡例を追加` にまとめる。`l l` で見ると、コミットの数は 3 つのまま。

`c f` は修正用のコミット (`fixup! 凡例を追加` というメッセージになる) を作るだけで、まとめるのは `r f` を押したとき。
修正をいくつかためてから、まとめて片付けたいときに使う。

## ブランチを main の先に付け直す

`feature` を作ったあとで、`main` にも `README に説明を足す` のコミットが入っている。

- [ ] `l b` で、`main` と `feature` が分かれているのを見る。`q` で閉じる。
- [ ] `r e` を押し、`Rebase onto` と聞かれたら `main` を選んで `RET`。
      `feature` の 3 つのコミットが、`main` の先頭の後ろに付け直される。`l b` で、履歴が一直線になったことを確かめる。

この状態なら、`main` に `feature` をマージ (レッスン 6) すると早送りになり、マージコミットのない一直線の履歴になる。
rebase の途中で衝突したら、レッスン 6 と同じように解決して stage し、`r r` で続ける。
